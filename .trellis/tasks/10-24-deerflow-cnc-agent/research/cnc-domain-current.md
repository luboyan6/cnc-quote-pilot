# 调研：现有 CNC 领域能力与 DeerFlow 工具边界

- 调研目标：明确 DeerFlow Lead Agent 工具可复用哪些现有的 CNC 业务能力，哪些功能仍未实现，以及集成过程中必须保留哪些契约与验收门禁？
- 调研范围：内部；只读代码审查、规范/任务/技能检查，无产品代码实施或线上浏览器实操。
- 日期：2026-10-24

## 调研发现

### 当前状态与权威决策

账号管理/登录以及单配置的 Run/Intent 属于真实产品代码，且具备完备的隔离测试。**然而，两个平台的线上真实报价功能均未启用：** `backend/app/modules/cnc/quote/providers.py:25` 在第 30 行恒定返回 `None`；`quote/runner.py:117` 因缺少适配器绑定而抛出 `PROVIDER_AUTOMATION_UNVERIFIED`。安装站点技能并不能改变这一事实。仅仅构建一个调用现有报价 API 的 DeerFlow 连接器，根本无法满足自动报价的验收要求。

必须以当前源码和基于源码的规范作为已实现行为的唯一判定标准。旧方案描述的是目标行为，并非实现证明。最近的历史交接文档为 `.trellis/tasks/10-23-cnc-part-config-auto-quote/research/site-skills-completion-2026-10-24.md:25`，其明确指出了两个平台的线上真实验收仍然处于开启（未完成）状态。较早的父任务 `execution-status.md` 中包含已失效的 DNS 排查记录；关于这一细节以浏览器规范及最新的 DNS 调研为准。

**账号与会话实现。** `cnc_account/service.py:38` 将非超级用户的访问严格限制在创建者范围内；`:62` 在 CRUD 操作前执行加解密封装；`:69` 保留空密码输入、对变更凭据/平台/认证方式/停用的账号执行会话吊销，并清空旧状态。`login/credentials.py:10` 使用既有的 `CryptoUtil`；公共的 `cnc_account/schema.py:33` 排除了密码、密文及租约秘密，但包含了完整用户名，因此面向大模型的账号工具需要更进一步的数据脱敏视图。

`LoginRepository.load`（`login/repository.py:47`）在服务端解析平台与凭据，并在独立的事务中将遗留明文迁移为密文。租约的获取/续期/释放（`:76`、`:102`、`:116`）采用所有者/Token/过期时间的隔离栅栏；续期时会检查最终的 `UPDATE ... RETURNING` 条件结果。绝不能在 Agent 进程中重复实现租约逻辑。`LoginManager`（`login/runtime.py:74`）持有同一个浏览器 Page，最大容量 4，有界命令队列 16，空闲 300 秒/存活上限 1800 秒，并具备输入节流。它仅在报价页面显式完成身份认证后才导出加密状态（`:168`）。请求/所有者隔离及报价独占见 `:126`、`:134`；任务完成后清理敏感信息（`:325`）。当前多 Worker 部署需要采用账号亲和性路由或单浏览器 Worker。

`login/providers.py:127` 通过受控的 Page/Context 检查返回的身份字段，而非通过 Cookie、URL、头像首字母或不受保护的 HTTP 客户端。Xometry 检查 `/v2/users/me`（`:225`），嘉立创检查 `/cncPortal/login/queryLoginUser`（`:232`）。Xometry 分离式登录与嘉立创原生 CAS iframe 逻辑位于 `:154`。`resolve_provider`（`:238`）校验审查通过的精准 HTTPS 入口域名；平台数据表中不包含具备权威性的 Provider 代码或启用状态注册表。账号表历史遗留的 `login_url` 字段绝不能作为 Agent 自由导航跳转的依据。

**冻结的文件与参数。** `QuoteRepository._objects`（`quote/repository.py:129`）将 `config.site_type` 作为关联平台的实际主键。模型旧注释中的 `1=Xometry,2=JLC` 绝不能当作路由判断逻辑。`accounts/snapshot`（`:147`、`:157`）执行平台/操作者/启用状态的校验；0 个可用账号则报错，1 个自动选中，多个则要求用户选择。`parameters`（`:63`）包含材料、正整数数量、可选表面处理及规范的标量附加参数，拒绝名称冲突、NaN 及复杂对象。适配器必须对未知或存在歧义的平台配置映射报错，严禁在合金牌号、热处理或表面处理上暗中近似处理。

`source_file`（`:84`）要求显式的上传授权、受信任的上传根目录限制、规范命名、文件大小/元数据一致性，支持大小写不敏感的 `.step/.stp/.setp`，并对冻结字节计算哈希。`validate`（`:178`）在执行任何远程变更前重新核验当前账号/配置/零件/RBAC 权限及文件一致性；实际上传始终使用原始不可变 Buffer。`browser/files.py:20` 为官方 SDK 提供的是泛化的私有文件名 `part.step`，而非服务器本地路径。本地 100MiB 的资源上限（`quote/repository.py:45`）并非平台已验证的上传限制。现存的文件校验尚未包含 CAD 几何有效性/可加工性检查；见 `.../research/continuation-2026-10-23.md:17`。

**运行与结果真实性。** `quote/authorization.py:19` 在独立会话中重新加载有效用户/角色/菜单，复用权限集合，包括超管权限降级。`AuthSchema` 本身无法标识特定的登录会话，不能声称其证明了单会话退出即时生效。现存的读取/启动/状态/指令路由（`quote/routes.py:40`）同时强制执行对象权限与固定 Schema。`QuoteRunView`（`quote/contracts.py:48`）刻意排除了原始 DOM、本地路径、远端引用/URL 及敏感秘密。`QuoteResult`（`:34`）包含高精度十进制金额字符串、明确的币种与单件/整单范围、原始强类型工期、请求值与实际生效值，以及可为空的税费/运费字段。

`QuoteActivity.advance`（`quote/runner.py:106`）先进行只读身份核验，随后在既有所有者上执行有界推进。外部 `await` 之后会重新校验每次远程变更；解析耗时较长时采用只读对账（`:136`），设定 180 秒/90 次观测的严格上限，绝不重新上传。`resume`（`:90`）就地核验而不离开当前页面。`validate_quote`（`browser/workflow.py:210`）要求严格匹配 Run / 生成代数 / 文件 / 回执 / 参数 / 几何体有效性、正数有限 Decimal 金额、已知币种/结算基准、受支持的工期语义及校验当次新鲜度。`runner.py:236` 针对估算价/待审核单独校验显式的当次 `ProvisionalQuote` 凭证。单凭未知价格不能推断为处于人工审核状态。`runner.py:233` 在广播终态成功前先提交事务。私有执行凭据与冻结快照一同存储（`repository.py:250`），不直接在公共视图中透出。

**重试与不确定意图。** `browser/workflow.py:60` 仅对审查通过的读取超时进行重试，最多 2 次。`_mutation`（`:126`）先持久化提交唯一的意图记录，严格仅执行一次远程操作尝试（`:162`），核验回执并确认。对已占用或处于不确定状态的操作仅执行只读对账；确认失败、取消或重启绝不能清空占用以进行重复操作。`DurableIntentStore`（`quote/repository.py:332`）强制校验 run/scope/fingerprint/generation/operation；唯一性约束刻意将可变的指纹排除在操作身份之外。若本地 Worker 丢失，`quote/service.py:63` 会抛出 `QUOTE_WORKER_UNAVAILABLE_NO_RETRY`。安全的取消逻辑（`repository.py:270`）不能直接终止其他活跃的 Worker；过期结算时会将未结清的占用标记为不确定，并释放对应的活跃配置。现有服务尚未实现透明的重启后接续执行能力。

### 建议的 DeerFlow 工具/服务边界（全新设计，非现有 API）

保持本项目的数据库、用户权限认证、加密账号、文件存储、浏览器执行所有权、工作流、意图及报价校验器的唯一权威性。`agent-platform` 应仅作为 Lead Agent / 技能 / 中间件的代码参考，通过受信任的服务端桥接调用精简的 CNC 领域服务。在服务端强绑定操作者身份及已授权的线程/运行/能力；绝不从模型参数中接收 `actor_id`、所有者、角色、凭据或 Bearer/Session 数据。

建议的工具集划分：

| 工具族 | 允许模型传入的参数 | 复用 / 新增的服务端契约 |
| --- | --- | --- |
| 发现已授权的平台/账号/零件/配置 | 分页/过滤条件及已授权的记录 ID。 | 复用带权限的数据读取；返回脱敏的账号元数据与安全的文件名/参数，不透出完整的账号明文 DTO 或服务器路径。 |
| 确保登录 / 查询登录状态 | 账号 ID。 | 复用 LoginRepository + LoginManager；返回脱敏状态及供前端进行人工接管的内部业务标识。人工键盘输入/点击仍在模型工具之外。 |
| 发起 / 查询 / 取消报价 | 配置 ID、符合条件的账号 ID、已知的 Run 引用。 | 复用 QuoteService；桥接层生成并保存稳定的逻辑操作/请求标识，防止模型重试或新工具调用 ID 造成重复写操作。 |
| 发起 / 查询 / 取消批量任务 | 已授权的配置/零件引用、精确的数量集合 `[1,2,5]`、核验过的平台映射。 | 全新持久化批次/子项服务，具备不可变的子项参数快照、准入去重、队列管理与聚合输出。切勿通过修改共享的 `config.quantity` 来实现多数量连续报价。 |
| 创建 / 更新 / 暂停监测方案 | 已授权的冻结目标引用及经过校验的频率/时区参数。 | 全新持久化方案/轮次服务；现有的 SchedulerUtil 内置组件仅在唯一 `(plan, scheduled_for)` 下入队待办轮次。模型严禁传入任何代码或 Cron 处理函数字符串。 |
| 读取结果 / 历史 / 凭证 / 诊断 | 已授权的 Run/Batch/Plan/凭据 ID；预设的过滤条件。 | 全新受 ACL 保护的列表/历史/报表/存据读取服务；提供脱敏的固定失败原因与有界页面摘要用于异常恢复。严禁暴露通用的 URL/本地路径/DOM/JS/Shell/浏览器上下文工具。 |

在桥接层与领域服务间采用严格的 Schema 与输入限制，每项操作均执行现有的 RBAC 与对象权限核验，并通过私有路由模式分发脱敏错误与审计事件（`login/routes.py:16`、`quote/routes.py:26`）。账号密码始终通过现有账号界面与写入端点进行配置，切勿将聊天消息或技能参数用作凭据载体。新增截图必须私有存储，绑定到对应的 Run/文件/参数代次，并按授权的凭据 ID 提供访问。网页 DOM 内容为不可信数据，绝不能当作扩充操作范围、篡改参数或伪造价格的指令。

技能必须能够通过 DeerFlow 技能接口被发现与调用，但实际执行必须严格路由至上述受限的领域工具。现有的站点 Markdown 可作为初始素材；仅仅加载 Markdown 技能本身并不等同于创建了平台适配器，亦无法满足调用/报价门禁。在智能体配置中必须显式禁用不必要的记忆、沙箱、通用文件系统与 Shell 工具。即使排除可选的智能体记忆与沙箱，底层的业务持久化、意图记录与账号会话存储仍属不可或缺的基础。

### 迁移与集成需求及潜在陷阱

1. 完整保留 `cnc_quote_run`、`cnc_quote_intent` 以及加密账号数据列。数据库迁移 `backend/app/alembic/versions/2026_10_23_1600_c9e3a6b72f14.py:15` 基于 `0ce906be2d99`；磁盘上最新的版本文件 `2026_10_23_1811_4e51456ea4db.py:16` 基于 `c9e3a6b72f14`。在编写新迁移前必须先核对实际部署的数据库版本，切勿盲目升级无关迁移。
2. 按照最终设计补充持久化批次/子项表、监测方案/轮次表、追加写入的观测记录表、事件/耗时/凭证记录表以及操作者/线程/操作映射。Run 的 `public_view` JSON 可用于辅助展示，但不能作为历史查询与对比的标准协议。必须记录适配器/技能/工作流/配置的版本、完整生效参数、文件哈希及商务范围；不同轮次观测到相同价格必须作为独立记录保留。未知或不一致的币种、数量、表面处理、材料状态、税费/运费、折扣或交期选项必须阻断严格的价格变动比对与排序。
3. 当前 Run 的唯一性约束为 `(actor_id, config_id, request_id)` 以及可为空的唯一 `active_config_id`。现有的幂等 `start` 在比较新请求内容之前会优先返回已有 Run。新的多输入准入 API 需要冻结请求指纹，并具备“同 Key 不同内容”的冲突拦截机制。现有 Intent 仅保护单个 Run，无法覆盖该样本后续的所有新建 Run：必须补充或复用显式的对账规则，使得新的操作标识无法绕过既有未结清的副作用。
4. Runner 代码写死了执行代数 `"1"`，并从 `run.frozen.requested` 中提取意图指纹。批次任务中的数量覆盖需要独立的不可变逻辑子项/Run；无法直接向现有 Run 传入覆盖参数而不破坏其契约。必须保持串行账号独占以及有界的资源占用上限。
5. 前端生命周期差异：`useAutoQuote.ts:69`、`:82`、`:282` 在弹窗或页面关闭时会取消未终结的 Run。而后台批量/定时任务需要独立于聊天窗口加载状态的、明确由用户掌控的生命周期，并具备独立的取消动作；切勿静默套用页面关闭即取消的策略。继续保持串行轮询、中断/Epoch 屏障以及过期 Run 标识校验。
6. `QuoteService.activities` 与 LoginManager 的所有权属于单进程内存状态。仅有数据库持久化记录无法直接提供多 Worker 或进程重启后的自动接管；需选用基于账号亲和性的单消费者架构，或设计完备的分布式 Worker 调度协议。在真正的只读恢复能力实现前，保持明确的“服务不可用/需人工介入”状态反馈。
7. 嘉立创仅能获取参考估算价是一个客观交付风险。系统可诚实交付并展示该估算价路径，但正式报价验收应保持开启状态。若该网站确实无法提供经核验的纯报价正式路径，应显式由产品层面决策；绝不可通过修改枚举值或将估算价偷换为正式报价来强行使测试变绿。
