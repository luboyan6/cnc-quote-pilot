## Goal

完成文件平台数量组合、幂等限流、持久监测计划和可比历史，形成两轮真实有效观测

## Source and Scope

父任务：[CNC MVP](../10-21-cnc-pricing-mvp/prd.md)。追溯 MVP-R05/06/07/10/11/13/14、FR-03/04/05、DV-08/09/11。

## Requirements

- 2 图 × 2 家 × 数量 1/2/5 精确展开 12 明细，持久入队、进度、失败重跑和取消可用。
- API 幂等键、同批 item 去重、账号互斥、平台限流、租约和提交不明协调不因重试重复计成功。
- 固定周期计划持久化，重复 tick/重启不重复建任务，错过/重叠轮次有明确记录。
- 观测追加保存，至少两轮真实自动触发；同价保留，缓存未核实不计监测成功。
- 完整参数/商业口径快照控制历史分组，不混比币种、税运、公差、数量、材料、折扣与交期档。
- 运行期活跃时间、等待、失败、恢复与人工介入有可复算记录。
- 批量/定时按每家独立 JSON 和固定版本加载，保留 Finish/颜色/Roughness/外观件/嵌件/检验等全部有效参数及未知状态，不能在下一轮静默采用修改后的默认值。
- 批量/定时共用固定 Workflow；每 item 的步骤/版本/intent 独立，发生未知异常才进入 Deep Agents 恢复分支并绑定 incident/thread。所有恢复共享该 item 预算和幂等，重启/取消/人工恢复按记录位置，不将模型 todo 当完成状态。

## Acceptance Criteria

- [ ] M-01：12 明细组合完整，无少项/重复；同键三次创建仅一个 task，同键异参 409。
- [ ] M-02：默认一个自动运行、同账号最多一个 context，暂停人工上下文总资源不超过 SRS。
- [ ] M-03：两轮自动计划生成新 task/item/观测，旧历史不覆盖；重复 tick/重启无重复触发。
- [ ] M-04：同价新观测保留，关键参数变更分组；严格可比才算差额。
- [ ] M-05：超时、取消、故障恢复、账号等待、丢回执和截图存储失败处理有界且完整。
