# CNC 批量执行、定时检测、异常处理与结果展示

> 2026-10-28 修订；状态 planning。本轮用户明确授权将已给出的四模块方案创建为 Trellis 任务，尚未授权启动产品实现。本任务复用原目录并作为四个子任务的规划/集成父任务。

## 目标与用户价值

在已完成的账号管理和自动报价之上，让用户批量执行多配置、多数量的询价，按周期检测价格，在异常时获得明确状态与可控恢复，并查看可追溯、可比较的结果和证据。

## 背景与依据

- 用户提供的技术设计附件已留存为 [需求来源](research/source-technical-design-v1.0.md)，本轮范围与源码证据见 [修订记录](research/planning-revision-2026-10-28.md)。
- 现有账号、单次报价、Run/Intent、APScheduler 和结果页面是复用基础。源码可见的账号隔离、持久执行和结果口径缺口归对应子任务补齐。
- 本轮四项功能采用确定性流程。旧 Deep Agents / DeerFlow / 五天交付前提不作为本轮依赖；[旧规划快照](research/legacy-planning-2026-10-28/)和其他任务历史验收保持原状。
- 用户说明基础功能已完成，不据旧任务状态重新实施账号/单次报价，也不补勾未执行的真实平台验收。正式报价、系统参考价与待审核保持平台原始性质。

## 跨子项验收标准

以下均为待执行验收，不因任务文件创建而通过。

- [ ] AC-01（R-01）：2 份图纸各有 2 平台配置、数量 1/2/5 精确形成 12 子项，无少项或重复；重复请求返回同批次，同键异参冲突。
- [ ] AC-02（R-02）：创建后修改原数量/材料或文件，既有子项不采用新输入；数量覆盖不修改配置表，变更可明确失败并重建。
- [ ] AC-03（R-03/04）：同账号/同配置不并行；单项失败后其他可执行项继续，刷新/关闭批次页不终止执行。
- [ ] AC-04（R-03/11）：每项尝试、Run、结果、文件及参数快照可关联；同 Run 终结回调重复到达仅一个结果。
- [ ] AC-05（R-04/05）：取消待执行/运行/人工等待项后无新自动操作，旧回调不能覆盖取消/新尝试；已发生副作用和结果保留。
- [ ] AC-06（R-05）：网络、过期会话、限流、参数错误、人工认证、丢回执、存储失败分类正确且预算有界；重启不盲目重传。
- [ ] AC-07（R-06）：重复 tick、并发扫描、扫描事务崩溃/重启不重复创建同一监测轮次。
- [ ] AC-08（R-06/07）：暂停/恢复、前轮未完、漏跑、队列满和权限撤销均符合共享契约并可查原因。
- [ ] AC-09（R-07）：两轮实际自动触发产生不同轮次、Run 与观测；相同价格保留两次，无历史覆盖。
- [ ] AC-10（R-08）：正式报价、参考估价、待审核、失败、取消和人工等待独立显示；成功率分子/分母与子项记录可复算，零分母显示暂无结果。
- [ ] AC-11（R-09）：参数、币种、数量、商业口径或报价性质不一致不连成同一可比序列；未知价格不画零价，金额精度往返保留。
- [ ] AC-12（R-10）：跨用户列表/统计/历史/尝试/截图访问被拒绝；证据私有、无存储路径和会话秘密泄漏。
- [ ] AC-13（R-11）：现有账号登录、单次报价及配置页面定向回归通过；JLC 参考价不会因此被标成正式报价。
- [ ] AC-14（R-03～11）：真实 PostgreSQL 并发与迁移检查、后端定向回归、前端类型/交互/构建及真实平台监测分别记录结果和未验收项。

## 范围外与延期

本轮不新增报价平台、重新开发账号 CRUD、引入 Agent/LLM 编排、Celery/Beat、微服务或跨主机执行。不实现复杂 Cron/日历、自动换汇、邮件/企业微信告警、下单/支付。首期固定周期与现有两个平台，结果展示扩展当前 Vue/ECharts。导出可沿用已有机制，新增报表导出不作为本轮硬验收。

## 风险与实施边界

- 当前快捷报价路径的账号/租约、进程所有权与结果落库缺口必须先随 T1/T2 收敛。
- 第三方页面可变；正式报价可用性和两轮真实监测单独验收，参考估价不代替正式报价。
- 当前工作区有大量用户未提交修改；只修改本任务责任文件，不覆盖并行工作。迁移以实施时实际 head 为准。
- 需求决策已按用户要求收敛；当前无阻塞规划的产品问题。实施启用、部署数据库检查和真实平台执行记录属于后续阶段。
