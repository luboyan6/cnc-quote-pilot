# T3：CNC 定时检测、监测计划与轮次

> 状态 planning；父任务：[四模块闭环](../10-21-cnc-mvp-04-monitoring/prd.md)。依赖 [T1](../10-28-cnc-monitor-01-batch/prd.md) 的批次准入、[T2](../10-28-cnc-monitor-02-recovery/prd.md) 的可靠恢复。

## 目标

用户将已确认的配置/账号/数量保存为固定周期监测计划，定期生成可追踪新轮次；暂停、重叠、漏跑或故障均可解释，不产生重复报价或伪造历史观测。

## 确认事实与依据

项目已有 APScheduler 3.11.0、选主/Job Store、builtin 白名单和节点生命周期；执行包装器是同步函数。见 [源码证据](../10-21-cnc-mvp-04-monitoring/research/planning-revision-2026-10-28.md) 的 ap_scheduler.py:62/96/726、database.py:93。本项复用该调度器，不建立第二套持久调度实例。

## 需求

- S-01（父 R-06）：创建/编辑固定分钟周期计划，显示时区、目标、下一执行时间和最近轮次。
- S-02（父 R-06）：计划每个时点只准入一个轮次/批次；重复扫描、重启或并发请求不重复执行。
- S-03（父 R-02/07）：计划版本与轮次输入可追溯；修改计划不会污染已生成批次。
- S-04（父 R-06/07）：暂停停止未来触发，恢复从下一有效未来时点开始；旧批次可另外取消。
- S-05（父 R-07）：前轮未完记录跳过，停机漏跑记录缺口；队列满保持可恢复时点，不伪造成功轮次。
- S-06（父 R-07/10）：每轮实际采集追加观测，即使同价；失权/账号停用暂停计划并给出明确原因。

## 验收标准

- [ ] S-AC01：合法固定周期可创建并持久保存，重启后 next_run_at/时区/目标版本可查；非法周期或无权目标被拒绝。
- [ ] S-AC02：重复 tick、两个扫描事务、提交前后故障与重启只产生唯一 schedule_id+scheduled_for 轮次及批次。
- [ ] S-AC03：round/batch/items/next_run_at 同事务；队列满不留半条轮次，并保存可恢复容量等待；创建失败与等待标记之间发生崩溃时按契约记录漏跑原因。
- [ ] S-AC04：暂停/扫描并发有确定提交先后；恢复不回补过去报价，旧批次不被隐式取消。
- [ ] S-AC05：前轮未完为 SKIPPED_OVERLAP，停机漏跑为 MISSED；长停机处理有界，时间推进不漂移。
- [ ] S-AC06：修改计划产生新版本，原轮次仍使用旧快照；源配置失效不会静默采用新参数。
- [ ] S-AC07：无前端观察时连续两轮实际自动触发，每轮新增 Run/观测；相同价格保留两次，参考价保持原性质。
- [ ] S-AC08：计划创建者失权、账号停用时不再自动 mutation，计划暂停且原因可见；无权限用户不能查看/控制计划或轮次。

## 范围外与交接

首期固定周期，不做复杂 Cron/节假日规则、自动补跑历史报价、Agent 触发或外部通知。向 T4 交付计划/轮次 API 与 batch/round/result 关联。真实两轮验收需当前平台实际可用，测试模拟和真实记录分开。
