# T1：CNC 批量执行与共享执行入口

> 状态 in_progress；父任务：[四模块闭环](../10-21-cnc-mvp-04-monitoring/prd.md)。用户于 2026-10-28 明确要求按本计划开始任务，已启动实施；验收证据见 implement.md 与 check-report.md（检查完成后生成）。

## 目标

用户可将已有图纸平台配置按数量集合展开为持久批次，查看每个子项的进度与结果；重复请求、并发点击、关闭页面或单项失败都不会造成任务丢失或错误复用。

## 确认事实与依据

单次服务的进程内启动、配置快照、Run/Intent 和唯一 active_config 已存在；JLC 快捷路径有固定账号/共享会话，结果保存缺少可靠终结约束。定位见父任务 [源码证据](../10-21-cnc-mvp-04-monitoring/research/planning-revision-2026-10-28.md) 中 service.py:50、repository.py:180/314、model.py:21、jlc_quote_service.py:160/243。用户将账号管理和单次报价列为已完成基础，本项只补齐批量复用所需边界。

## 需求

- B-01（父 R-01）：批次创建前可预览展开组合、确定各配置账号与数量；非法目标或队列满整体拒绝。
- B-02（父 R-01/02）：重复请求幂等，同键异参冲突；输入固定，数量覆盖不改共享配置。
- B-03（父 R-03/04）：子项独立排队、执行、显示进度；同账号/同配置互斥，失败不阻断其余可执行项。
- B-04（父 R-04）：刷新/关闭批次页不终止后台批次；显式取消可停止待执行项并向执行中项发出可追溯请求。
- B-05（父 R-03/11）：子项、尝试、单次 Run 和结果可关联；重复完成通知不生成重复结果，落库失败不显示采集完成。
- B-06（父 R-10/11）：统一当前权限、账号隔离、文件复验；现有单次 API 和受控人工处理继续可用。

## 验收标准

- [ ] B-AC01：2 图纸 × 2 平台配置 × 数量 1/2/5 精确生成 12 子项；预览与最终创建一致。
- [ ] B-AC02：同一请求并发提交三次只有一个批次；相同 request_id 修改数量返回冲突；容量不足和非法目标不留下部分批次。
- [ ] B-AC03：创建后改原数量/材料/文件，旧子项不会采用新值；源配置表未被数量覆盖修改，失效来源有明确原因。
- [ ] B-AC04：同账号、同配置竞争均保持互斥；不同数量不会关联同一个不匹配的活动 Run；单项失败后其他项继续。
- [ ] B-AC05：关闭/刷新观察页后任务继续；待执行取消无浏览器操作，运行取消有确认状态且保留结果/Intent。
- [ ] B-AC06：每个尝试关联唯一 Run；完成回调重复到达仅一条结果；存储失败不进入公开 COMPLETED。
- [ ] B-AC07：跨用户创建/读取/取消和不匹配平台账号被拒绝；JLC/Xometry 都实际使用选定账号，平台路由不依赖固定 1/2。
- [ ] B-AC08：现有登录、单次报价 API/参数/关闭行为和 CRUD 定向回归通过；原 REFERENCE_ESTIMATE 性质保留。

## 依赖与交接

前置是核对现有账号/单次报价契约及实际数据库迁移 head，不要求先重做这些模块。交付给 T2 的是持久子项、稳定尝试关联、受控执行入口、取消请求与领取令牌；复杂分类重试与崩溃核对由 T2 完成。

## 范围外

本项不做定时计划、新结果页面、多进程执行、自动猜测人工声明或增加新平台。不以取消/重试删除已有不明 Intent。
